# 后端与 Windows 桌面集成规范

## 1. FastAPI 分层

职责边界：

- `application.py`：创建 FastAPI、注册中间件与 Router。
- `api/`：按领域组织 Router，只做输入校验、调用与响应映射。
- Service / use case：下载、翻译、任务编排等业务规则。
- Repository / `db.py`：SQLite 查询、事务和记录转换。
- Adapter / `scraper.py`：第三方站点、OCR、文件格式与外部模型协议。

新增业务不得继续堆入单一入口。修改现有大型模块时，优先将正在变更的完整用例提取到对应层，并保持测试覆盖。

## 2. API 约定

- 业务 API 使用 `/api/v1` 前缀；`/healthz` 仅供进程与 systemd 存活检查。
- API 只暴露必要字段，使用 Pydantic 模型验证输入输出。
- 资源不存在返回 `404`，校验失败返回 `422`，业务冲突使用 `409`。
- 错误正文使用稳定的 `detail`，不得返回 Python 堆栈、密钥、Cookie 或本机完整隐私路径。
- 列表排序和分页规则必须确定；任务状态使用稳定枚举值。
- 长任务立即返回任务记录，通过轮询查询进度，不让单次请求无限等待。
- 客户端与服务端日期格式保持一致，并明确时区语义。
- 对外 DTO 不得包含 `localPath`、`filePath`、数据目录、内部文件名或服务器绝对路径。
- 认证后的 `/api/v1/meta` 返回服务标识、应用版本、API 版本、实例 ID 与运行能力，客户端保存连接前必须校验。

本机默认端点为 `http://127.0.0.1:19453`。未配置认证时服务必须拒绝监听非回环地址。
Linux 远程后端在反向代理或私有网络之后运行，业务 API 必须启用 Bearer Token；公网访问必须使用
HTTPS，FastAPI 不直接承担公网 TLS 终止。

### 认证与凭据

- `/healthz` 不认证，只返回稳定的存活状态，不包含版本、路径或配置。
- `/api/v1/*` 默认全部认证；Token 从 `Authorization: Bearer` 读取并使用常量时间比较。
- 服务端只保存高熵 Token 的 SHA-256 摘要；启动日志、异常与 OpenAPI 不得显示原始 Token。
- Windows 客户端将 Token 保存到系统安全凭据存储，普通偏好只保存连接模式和根地址。
- 设置读取不返回翻译密钥或账号密码明文，只返回是否已配置；更新使用“保留、替换、删除”语义。
- 认证图片与导出下载遵循相同规则。客户端只向配置后端的同源 URL 附加 Token，避免泄露给第三方封面或重定向目标。
- 当前后端是单用户服务：所有有效 Token 客户端共享书架、任务、设置和阅读进度，不提供用户隔离。

## 3. 数据库与文件

- 所有 SQL 使用参数绑定。
- 需要多步一致性的写操作使用事务。
- Schema 变化必须提供可重复、可回滚或可恢复的迁移策略。
- 删除书籍前解析并校验目标路径，不能删除文库根目录或任意用户路径。
- 文件名清理非法 Windows 字符，并处理保留名、尾随点和长度限制。
- 数据目录通过 `QINGJUAN_DATA_DIR` 或统一解析函数确定，禁止在业务代码散落绝对路径。
- 数据库、封面、章节、译文和临时文件的所有权必须清楚。
- 数据库存储相对数据根的稳定存储键，不把机器绝对路径作为跨请求、备份或迁移标识。
- SQLite 启用 WAL、外键和有限 `busy_timeout`；当前任务队列与链接任务要求单进程、单 Uvicorn worker。
- 时间字段对外使用 UTC ISO 8601；旧的无时区字段迁移时按明确的服务器本地时区解释。

## 4. 抓取与外部服务

- 网络请求设置连接、读取和总超时；重试必须有上限和退避。
- 验证 URL scheme，只允许业务需要的 `http` / `https`。
- 防止 SSRF：拒绝环回、链路本地、私有网段和不可信重定向，除非某个明确的本地集成经过单独授权。
- 控制并发，避免对第三方站点造成突发压力。
- 解析器按站点或协议拆分，通用清洗与持久化逻辑复用。
- 站点 HTML 变化视为正常故障，错误应指出站点和阶段，不吞异常。
- 翻译和 OCR 请求不得记录原始密钥；正文日志要限制长度。
- 尊重目标站点条款、robots、版权与用户所在地区法律。
- 番茄小说作品页解析服务端渲染的 `window.__INITIAL_STATE__`，目录以 `chapterListWithVolume` 为准。`isChapterLock`、`needPay` 等字段作为访问状态提示保留在目录中。导入请求通过 `downloadMode` 明确选择 `all`（全部下载）或 `on_demand`（边看边下）；旧客户端未传该字段时保持 `all`，桌面导入界面对番茄小说默认推荐 `on_demand`。章节下载时交叉校验正文字符数与章节声明字数；正文为空或仅有试读片段时返回可执行错误，完整正文则记录内容来源、访问方式和校验结果。
- Pixiv Comic 作品页通过同源作品与章节接口解析；阅读页签名只能使用页面下发的临时盐值生成，图片按接口提供的网格参数在本地无缩放复原。登录、购买或已结束公开的章节不得绕过访问限制。
- 翻译服务只维护一份 OpenAI 兼容配置，通过 `Authorization: Bearer` 调用 `/v1/chat/completions`；禁止重新引入按品牌区分的提供商分支。模型禁用时任何翻译任务都必须立即停止并返回可操作错误。

### 本地文档导入

- 小说格式支持 `TXT` / `TEXT`、Word `DOCX` 与 `EPUB`；旧版二进制 `.doc` 必须先转换为 `DOCX`。
- 漫画格式支持 `PDF`，导入时逐页渲染为本地 PNG，并作为单个漫画章节保存。
- 格式识别以后缀和内部结构校验为准，客户端选择的作品类型不能绕过后端校验。
- DOCX / EPUB 作为 ZIP 容器处理时必须限制条目数、解压后总大小并拒绝目录穿越路径。
- 大文件先按块写入 `DATA_DIR/import-cache/`，解析和 PDF 渲染在线程池执行；无论成功失败都要清理临时文件。
- 当前大小限制为文本 64 MB、DOCX / EPUB 256 MB、PDF 1 GB，PDF 最多 5000 页。

### 章节导出

- 已下载的小说章节支持导出为 `TXT`、`TEXT`、`DOCX` 或 `EPUB`，产物必须通过本地导入器的结构校验。
- 漫画章节支持导出为多页 `PDF`，也支持打包为 ZIP；ZIP 内按章节分目录，并按清单顺序使用 `001`、`002`……命名并保留原图片扩展名。
- 详情页顶部的“下载全部/下载所选”与单章下载按钮使用相同的格式选择流程；多章小说合并为一个文档，多章漫画 PDF 按章节与页面顺序合并，图片模式先创建作品目录再按章节分目录。
- 有有效译文或译图时优先导出翻译内容，否则回退到原始内容；不得混用已失效的译图缓存。
- 导出接口只在 `DATA_DIR/exports/` 生成受控产物并返回产物元数据与认证下载 URL，不接受客户端文件路径。
- 产物使用不可猜测 ID、固定有效期和定时清理；客户端流式下载完成后再原子移动到 Windows 用户选择的位置。

### 漫画图片翻译

- 处理顺序固定为文字检测与 OCR、分区翻译、原文清除、译文排版，不允许跳过 OCR 直接让生成模型改整张图。
- 默认先运行本地 RapidOCR，得到文字和坐标后再将纯文本交给 OpenAI 兼容模型翻译；翻译模型不得被假定支持图片输入。RapidOCR 使用随程序分发的 ONNX 小型模型，必须延迟初始化并复用单例，不得在应用启动或识别期间静默下载模型。RapidOCR 结果为空、失败或平均置信度不足时再运行 Windows OCR，并在两侧都有有效结果时合并；高置信度 RapidOCR 可直接进入翻译，避免等待重复识别。
- 只有用户明确开启“使用模型辅助识图”时才能向模型发送漫画图片。视觉模型用于补充竖排字、小字、描边字和拟声词；视觉候选必须先通过原图像素证据校验，未被本地 OCR 覆盖的候选还要经过第二次视觉识别确认。合并时按文字一致性与区域重叠裁决，冲突区域优先采用本地 OCR 文本。
- `bbox` 只表示紧致文字区域，`body_bbox` 表示气泡或旁白框，`safe_box` 表示可排版的安全内区，三者不得混用。
- 根据原图文字像素估算前景色、描边色、字号与粗细倾向；无法从像素可靠恢复字体名称时，使用支持目标语言的本机近似字体。
- 原文清除只能操作文字蒙版的膨胀区域：纯色气泡使用背景色回填，复杂纹理从蒙版边缘向内进行局部邻域修复，禁止使用整块模糊、重绘整个气泡或改变原图尺寸。
- 译文优先保留原文横排或竖排方向，以原字号为起点逐级缩小，必须完整放入 `safe_box` 并记录溢出、清除方式和平均原字号诊断。

## 5. 后台任务

任务至少包含：

- 稳定 ID、类型、资源 ID；
- `queued`、`running`、`completed`、`failed` 等状态；
- 总数、完成数、进度与用户可读消息；
- 创建、更新时间；
- 脱敏错误和分级日志。

任务执行器必须：

- 限制并发；
- 在资源被删除后安全停止；
- 重启后将未完成任务恢复为可解释状态；
- 失败时保留可重试信息；
- 不因单个任务异常终止整个工作进程。

## 6. Windows 后端进程生命周期

Flutter 客户端启动时：

1. 读取显式连接模式；
2. 远程模式调用认证元数据接口，成功后直接复用，失败时显示诊断且不启动本机进程；
3. 本地模式调用健康检查；
4. 已有健康服务则复用并标记为外部进程；
5. 否则依次查找发布目录 `backend/qingjuan-desktop.exe`；
6. 开发环境向上查找 `python-backend/app/main.py`；
7. 启动后在有限时间内轮询健康状态；
8. 失败时保留桌面 UI，并显示诊断信息。

退出时只关闭客户端创建的 `Process`。标准输出和错误输出必须持续排空，避免子进程因管道阻塞。
启动命令不使用 shell 拼接用户输入，工作目录和参数分开传递。

## 7. Windows Runner

- Runner 只负责窗口标题、尺寸、Flutter 引擎和系统生命周期。
- 默认窗口适合桌面内容工作流，推荐 1360 × 860，最小尺寸由布局约束保护。
- 产品名、文件描述、版本和图标保持一致。
- 原生插件必须说明用途、权限和卸载影响。
- 不在 C++ Runner 复制 Dart 业务逻辑。

## 8. 发布打包

`tool/build_windows.ps1` 是唯一完整发布入口：

执行前先完成[开发环境与依赖基线](./README.md#开发环境与依赖基线)，激活
`python-backend/.venv`，并确认 `Get-Command python` 指向虚拟环境。脚本会使用当前
`PATH` 中的 Python 和由 `requirements-dev.txt` 固定的 PyInstaller；不能用仅安装了
运行依赖的系统 Python 生成正式包。

1. 校验 Flutter `3.24.3`，缺少 NuGet 时下载固定版本并验证 Microsoft 数字签名；
2. `flutter pub get`；
3. `flutter build windows --release`；
4. 复制完整 Runner 目录；
5. PyInstaller 构建单文件后端；
6. 将后端放入 `backend/`。

默认拒绝使用其他 Flutter 版本生成正式发布包。仅为迁移验证新工具链时，才可显式传入
`-AllowFlutterVersionMismatch`；该参数生成的结果不能直接作为正式发布包。

发布目录必须整体分发。Flutter DLL、插件 DLL、`data/` 和后端可执行文件缺一不可。
发布前在干净 Windows 环境测试首次启动、数据写入、退出清理和无 Python 环境运行。

## 9. Linux 单用户部署

Linux 的权威部署入口位于 `deploy/linux/`，使用原生 Python 虚拟环境与 systemd，不提供 Docker、
Compose 或随仓库分发的反向代理配置：

- 服务器从 Git 仓库拉取代码到 `/opt/qingjuan/app`，虚拟环境位于 `/opt/qingjuan/venv`。
- systemd 仅运行一个 Uvicorn 进程；禁止多 worker、多实例或多个服务共享同一 SQLite 数据目录。
- 持久化数据固定在 `/var/lib/qingjuan`，服务配置与只供管理员查看的原始连接 Token 位于
  `/etc/qingjuan`，均不得提交到仓库。
- `QINGJUAN_AUTH_TOKEN_SHA256` 是非回环监听的必需配置；服务只读取摘要，原始 Token 不进入进程环境、
  命令行、普通服务日志或 API 响应。
- `QINGJUAN_BROWSER_EXECUTABLE` 指向系统 Chromium；Linux 不调用 Windows OCR，漫画本地识别使用 RapidOCR。
- systemd 日志通过 `journalctl -u qingjuan-backend` 查看；服务启动时输出公开连接地址、API 前缀、
  数据目录和认证状态，但绝不输出原始 Token。
- `sudo qingjuan-info` 从权限为 `0600` 的管理员连接文件读取原始 Token，并可在后续需要时再次打印，
  这是供 Windows 客户端配置使用的持久化入口。
- 直连 HTTP 仅允许在可信局域网、Tailscale/WireGuard 等私有网络中使用。公网访问仍必须在服务前配置
  运维方选择的 HTTPS 反向代理，FastAPI 不直接终止公网 TLS。

首次部署先在服务器拉取仓库，再运行安装脚本：

```bash
sudo mkdir -p /opt/qingjuan
sudo git clone https://github.com/Tavre/QingJuan.git /opt/qingjuan/app
cd /opt/qingjuan/app
sudo bash deploy/linux/install.sh
sudo qingjuan-info
```

安装脚本优先检测 Tailscale IPv4，再从服务器网卡选择私有 IPv4，自动生成 FastAPI 根地址并监听
`0.0.0.0`。不会联网查询或自动暴露公网 IP；检测不到私有地址时，必须先配置私有网络，或使用
`--url https://域名` 指定已配置 HTTPS 反向代理的地址。`--url` 不包含 `/api/v1`；只允许 SSH 隧道访问时
使用 `--url http://127.0.0.1:19453 --bind 127.0.0.1`。
安装脚本生成 32 字节随机 Token、写入服务端摘要、创建虚拟环境、安装 systemd 单实例服务并将连接信息
打印到控制台。后续更新使用：

```bash
sudo bash /opt/qingjuan/app/deploy/linux/update.sh
sudo qingjuan-info
```

卸载程序时默认保留 `/var/lib/qingjuan`：

```bash
sudo qingjuan-uninstall
```

需要同时永久删除书库数据时，直接执行 `qingjuan-uninstall --purge-data`。卸载脚本只允许删除固定的青卷目录，
并在保留数据时保留 `qingjuan` 系统用户，避免书库文件失去属主。

备份必须同时覆盖 SQLite 与书籍文件。默认做法是停止 `qingjuan-backend`，备份整个
`/var/lib/qingjuan` 后再启动；恢复到临时目录验证数据库与清单后才能替换生产目录。当前不承诺无停机
备份、多用户隔离、集群或对象存储。

## 10. 安全检查

- [ ] 无认证后端只监听 `127.0.0.1`；远程后端配置 Token 且由私有网络或 HTTPS 保护。
- [ ] `/healthz`、公开 DTO 和错误响应不泄露服务器路径或敏感配置。
- [ ] Token 只发送到青卷同源地址，设置接口不回传密钥明文。
- [ ] API 密钥、Cookie、正文和本机路径未进入日志。
- [ ] 文件删除、导出和导入路径经过边界校验。
- [ ] URL 与重定向经过 SSRF 检查。
- [ ] 子进程参数无 shell 注入。
- [ ] 客户端只终止自己创建的进程。
- [ ] 发布包不包含数据库、测试数据或开发密钥。
- [ ] 依赖许可证与 GPL-3.0 分发要求已复核。
- [ ] Linux 以 systemd 单进程单 worker 运行，数据目录、备份恢复和 Chromium/RapidOCR 能力已验证。

### 番茄章节解析

- `python-backend/app/fanqie_parser.py` 负责网页 `__INITIAL_STATE__`、目录锁定状态、正文 HTML 和自绘字体反混淆；未知字体映射保留原字符。
- 受限章节由 `python-backend/app/fanqie_app.py` 调用番茄阅读 APP 的全文接口，`fanqie_crypto.py` 实现请求签名、密钥注册响应解密和正文 AES-CBC 解密。密钥只保存在单次后端进程的内存中。
- 抓取顺序为网页完整正文优先，网页返回试读片段或限制提示时回退 APP 全文接口；两条路径都失败时章节保留为未下载并记录错误，不写入错误占位正文。
- `on_demand` 导入只保存元数据、封面和完整章节目录，不能在导入任务中抓取正文；首次打开章节时同步缓存当前章，响应成功后在后台顺序预取后续 20 章。预取失败只记录诊断，不阻断当前阅读，删除书籍或关闭后端时必须回收相关任务。
- `all` 导入保持逐章下载全部正文的离线流程。界面必须提示长篇作品可能耗时较久，且用户选择不能被章节数量自动覆盖。
- 设备参数可通过 `QINGJUAN_FANQIE_DEVICE_ID` 和 `QINGJUAN_FANQIE_INSTALL_ID` 覆盖；默认值仅用于匿名接口请求，不记录账号 Cookie。
- 固定样本验证命令：`Set-Location python-backend; python -m pytest tests/test_fanqie_parser.py tests/test_fanqie_app.py`。
