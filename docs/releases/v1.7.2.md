# 更新内容

## Linux 章节缓存与阅读优先级

- Linux 后端完成按需导入后，会从最早未缓存章节开始顺序缓存全部可访问正文；任务归应用生命周期管理，客户端断开不会取消，服务重启后会根据目录和已落盘文件继续。
- 用户打开章节时，当前章和下一章优先于后台顺序缓存。后端会合并同章并发请求、暂停或抢占较低优先级下载，避免阅读请求继续排在整本缓存队列之后。
- Flutter 阅读器在等待当前章时同步预取下一章，并显式标记预取请求，避免服务端递归扩大阅读窗口。Windows 本机后端仍保持轻量的当前章与相邻章策略。
- 单章下载失败只记录该章并继续缓存后续章节；目录持久化与正文网络请求使用更小的锁范围，减少同一本书不同章节之间的不必要串行等待。

## 模型端点与管理安全

- 翻译模型和外部 OCR 设置只允许带 CSRF 的管理会话修改；普通客户端 Token 只能读取缓存后的模型状态，不能修改设置或触发真实外部探针。
- API 密钥与规范化 Origin 绑定。切换到不同 Origin 时不再沿用旧密钥，管理员需要为新端点重新录入凭据。
- 模型与 OCR 出站请求默认只允许解析到公网地址的 HTTPS，拒绝回环、私网、链路本地、保留地址、云元数据、环境代理和自动重定向，并将连接固定到已校验 IP。
- 局域网自建模型可由 Linux 运维方通过 `QINGJUAN_MODEL_ENDPOINT_ALLOWLIST` 精确授权；重新运行安装脚本会保留已有白名单。管理界面补充相应提示，但不会显示白名单或敏感配置。

## Android 界面

- 底部导航改为范围受控的悬浮圆角液态玻璃表面，统一亮暗主题下的描边、阴影、选中态与触控反馈。
- 透明效果关闭或背景不适合采样时自动提高表面不透明度；模糊区域通过裁剪和重绘边界限制，避免扩大滚动期间的渲染成本。

- `pubspec.yaml`、Android、Windows 与 FastAPI 共用 `1.7.2+23` 版本源；正式发布标签为 `v1.7.2`。
- 固定 Flutter 3.24.3 下的 Dart 格式检查、Analyzer、132 项 Flutter 测试与 Android Release APK 构建已通过；Python Ruff、Compileall、232 项 Pytest，以及管理端 TypeScript 检查、25 项测试和生产构建已通过。

- 正式 Release 仍只在 PR 合并且 `main` 全部门禁通过后，由匹配版本的 `v1.7.2` 标签工作流发布并附带 SHA-256。

# 升级说明

- V1.7.2 可直接读取 V1.7.1 的 Windows 本机或 Linux 后端数据，不涉及数据库或导入格式迁移。
- Linux 上既有按需导入书籍会在服务启动后继续缓存未落盘的可访问章节；升级前请确认服务器磁盘和书源访问策略符合预期。
- 使用局域网 HTTP 模型或 OCR 服务的 Linux 部署，需要在 `/etc/qingjuan/backend.env` 中显式配置精确 Origin 白名单并重启后端；公网 HTTPS 模型无需新增配置。
