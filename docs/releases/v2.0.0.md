# 青卷 V2.0.0 更新日志

V2.0.0 是一次以 Linux 多用户、账号安全和跨端体验为核心的大版本更新。Linux 后端从共享书架升级为独立账号体系，并加入可组合注册验证、GitHub 登录、两步验证、用户管理和在线升级；Windows 本机模式继续保持开箱即用，不显示远程多用户功能。

## 版本亮点

- Linux 后端支持注册与登录，每位用户拥有独立的书架、阅读进度和任务数据。
- 新增邮箱验证码、固定身份牌、GitHub 登录和验证器应用 2FA。
- 管理界面新增用户管理、注册设置和后端在线升级。
- 重构移动端“我的”页面，优化主题选择、音量键翻页和桌面滚动体验。
- Windows 本机后端继续隐式使用管理员身份，多用户、注册、GitHub 和 2FA 入口全部隐藏。

## Linux 多用户与独立书架

- Linux 后端新增完整的用户注册、密码登录和会话管理。
- 书架、阅读进度、下载与翻译任务按用户隔离，管理员客户端也只访问自己的书架。
- 旧版本已有的书籍、阅读进度和任务在升级时自动归属内置 `admin` 用户，不删除原有数据或模型设置。
- 普通用户可以使用服务器已有的书源和插件；只有管理员可以修改书源、插件开关、翻译模型等服务级配置。
- 番茄、起点等用户登录态按青卷用户隔离。Bika 凭据仍属于管理员维护的全服抓取配置，不作为个人书架账号保存。

## 注册、登录与账号安全

### 邮箱与身份牌注册

- 自助注册始终要求填写唯一邮箱。
- 管理员可独立启用“邮箱验证码注册”和“身份牌注册”；两项同时开启时，新用户必须全部验证通过。
- 管理界面新增 SMTP 设置，支持 STARTTLS、SSL 和无认证本地 Relay。
- 邮箱验证码具有有效期、错误次数、重发间隔和来源限流保护；SMTP 密码、身份牌和验证码不会通过管理接口回显。

### GitHub 登录

- 管理员可配置 GitHub OAuth App Client ID 并启用 Device Flow，不需要保存 Client Secret。
- 用户注册并登录本地账号后，可在“账号安全”中自行绑定或解绑 GitHub。
- GitHub 只作为已有账号的登录方式，不会自动注册青卷账号，也不会申请邮箱或仓库权限。
- GitHub 临时访问 Token 只在后端内存中用于读取公开身份，不写入数据库、不返回客户端。

### 两步验证（2FA）

- 用户可绑定支持 TOTP 的验证器应用，验证码采用 6 位、30 秒周期，并允许有限时钟偏差。
- 启用 2FA 时生成 10 个一次性恢复码；恢复码只显示一次，使用后立即失效。
- 无论使用密码还是 GitHub 完成第一步登录，启用 2FA 的账号都必须继续通过验证才能建立会话。
- TOTP 密钥加密保存，同一时间步验证码不可重复使用；修改密码、角色、状态或账号安全设置后，旧会话会立即失效。

## 管理界面

- 新增用户管理页面，可创建和停用用户、编辑显示资料、重置密码、提升或降低管理员权限，并撤销用户的全部登录会话。
- 内置 `admin` 不能被停用或降权；服务器管理密码与客户端用户会话继续相互独立。
- 用户列表新增邮箱、GitHub 绑定和 2FA 状态，便于管理员核对账号安全情况。
- 新增注册设置页面，集中维护 SMTP、邮箱验证码、固定身份牌和 GitHub Device Flow。
- 新增后端升级页面，可检查和安装受信部署仓库的更新。下载、依赖安装和预检阶段服务保持在线，只在最终切换时短暂重启。
- 客户端会识别升级重启，显示等待恢复状态并自动重新连接；连接恢复后再执行模型健康检查，避免后端已恢复但界面仍误报异常。

## “我的”页面与跨端体验

- 参考移动端个人中心布局重构“我的”页面，重新组织账户状态、书架摘要、服务器连接和常用设置，删除无关区域。
- 未登录的远程用户只显示登录与注册入口，不再提前加载其他用户的书架或任务数据。
- 登录后可在账号管理中查看账户资料、绑定 GitHub、启用或关闭 2FA，以及重新生成恢复码；显示资料由管理员在用户管理页面维护。
- 移动端主题选择器在窄屏和大字体下会完整显示“跟随系统”，并改用适合手机的日间、夜间和自动主题图标。
- 音量键翻页改为顺序处理快速按键，跨章和弹层切换时不再误跳或在后台翻页。
- 桌面端鼠标滚轮采用短缓动并合并连续滚动输入；触控板、移动端以及“减少动态效果”设置继续保持原生响应。

## Windows 本机模式

- Windows 本机模式继续无需账号和连接 Token，默认以隐式管理员身份使用本机书架。
- 用户注册、登录、用户管理、GitHub 登录和 2FA 在界面及 API 层同时隐藏，不影响原有单机使用方式。
- 翻译模型、API 密钥、视觉能力、系统提示词和外部 OCR 改为直接在客户端“设置 → 翻译服务”中维护，不再跳转浏览器管理界面。
- 本机后端不启动 `/admin` 管理站点，只接受受信回环客户端的设置请求；模型和 OCR 密钥不写入客户端偏好，也不会由后端回显。

## 阅读与分页

- 分页阅读改为根据真实字体、文字缩放、行距、首屏标题和页脚高度测量内容，减少页尾截断和文字溢出。
- 分页优先在换行和中文标点处断开，并为极端窗口尺寸和无障碍文字缩放保留稳定的缓存失效与前进逻辑。

## 安全与稳定性

- 登录、注册和验证码发送不再因网络响应丢失自动重复提交。
- 仅更换同一后端地址的连接 Token 时，也会清空尚未提交的密码、验证码、身份牌和 GitHub 流程。
- 用户状态、权限、密码、2FA 和 GitHub 绑定变化通过认证版本与数据库原子校验撤销旧会话，避免并发请求恢复已经失效的登录状态。
- Windows 本机写请求要求专用非简单请求头，阻止网页借助回环地址触发导入、OCR 或设置修改。
- 模型、OCR、SMTP、身份牌、TOTP 和恢复码使用分离的保存与更新规则，敏感值不会进入普通响应或运行日志。

## 升级说明

- V2.0.0 可直接覆盖安装 V1.7.7；数据库迁移会在首次启动时自动、幂等执行。
- Linux 升级前建议同时备份 `/var/lib/qingjuan` 和 `/etc/qingjuan/backend.env`。后者包含独立稳定的 2FA 加密密钥，必须与数据库配套保存。
- Linux 安装或首次升级会自动生成 2FA 加密密钥；修改浏览器管理密码不会轮换该密钥。
- 普通卸载会保留书库数据和受限配置；只有 `qingjuan-uninstall --purge-data` 会永久删除二者。
- 从尚未包含在线升级器的旧版本迁移时，先运行一次命令行更新。若管理页面仍提示“尚未启用在线升级”，再次运行同一更新命令完成引导，之后即可在管理界面升级。
